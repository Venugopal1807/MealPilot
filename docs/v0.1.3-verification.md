# v0.1.3: reviewable correctness evidence

The starting working tree passed 59 tests and all 34 evaluation scenarios.
Those results did not establish correctness for cases absent from the fixtures.
Before changing production code, six regression test methods were added and run
against that working tree. All six methods failed, with eight failed assertions
including parameterized subtests. After the corresponding fixes, those same
methods passed. Later punctuation variants extend that regression family.

The v0.1.2 working tree was uncommitted. No historical Git reference, commit, or
push was created. The table below records the observed pre-fix run; the runnable
regressions now verify the fixed behavior rather than recreating an old checkout.

Verified final results for this implementation:

| Check | Observed result |
| --- | --- |
| Complete automated suite | 78 tests passed |
| Evaluation scenarios | 51 passed, 0 failed |
| Previously existing expectations | All 34 preserved unchanged |
| Seeded defects detected by required invariant | 10 of 10 |
| Measured scenario constraint/grounding/contract/access failures | 0 |
| Uvicorn HTTP smoke | Normal request, ambiguous stop, explicit disambiguation, structured compatibility, and v0.1.3 schema passed |

The local smoke server was stopped after verification. No application dependencies
were installed, commerce tools called, commits created, or changes pushed.

## Where the new guarantees are enforced

- [Intent boundary](../app/intent.py): the supported deterministic grammar is an
  acceptance policy independent of an injected parser. Accepted parsed meaning
  must match the request; ambiguous or unknown grammar stops. Schema validation
  still rejects malformed outputs. Semantically equivalent casing, whitespace,
  and ingredient-set ordering remain valid.
- [Candidate contract](../app/candidates.py): missing fields, empty/invalid
  ingredients, reserved unknown placeholders, and explicit incomplete-evidence
  flags invalidate the entire catalog before eligibility filtering.
- [Evaluation](../evaluation.py): provider calls and pre-execution snapshots are
  observed independently of returned output. All six candidate fields must match
  source evidence; multiplicity prevents invented duplicates. Response counts and
  source labels are checked too. Goldens for identical dish names specify full
  candidate records so swapping ties cannot hide behind matching dish/score pairs.
- [API tests](../tests/test_api.py): exercise actual malformed/truncated JSON,
  invalid UTF-8, missing files, mixed valid/incomplete records, and evidence flags
  using temporary local files. They assert generic errors without partial results.
  An invalid produced response separately verifies sanitized HTTP serialization
  failure, rather than assuming a direct function call proves HTTP behavior.
- [Domain invariants](../tests/test_optimizer.py): check all 120 permutations of
  the five-record mock catalog against an explicit ordered expectation and
  independent hard-constraint assertions. Tightened budgets/exclusions/requirements
  cannot introduce extra candidates.

All 34 prior evaluation scenarios retain their original expectations. Seventeen
new scenarios exercise the counterexamples, failure boundaries, and disambiguated
positive control. Provider/parser output fixtures are synthetic; the production
mock implementation and catalog are unchanged.

## Evaluate the evaluator

The normal evaluation command runs ten named, seeded defects in local function
references. API handlers and catalog files are not patched or rewritten.

| Seeded defect | Required detecting invariant |
| --- | --- |
| Return an over-budget candidate | Hard constraints |
| Return an excluded ingredient | Hard constraints |
| Fabricate a price while preserving dish and score | Catalog grounding |
| Duplicate a candidate beyond source multiplicity | Catalog grounding |
| Corrupt response count | Response contract |
| Reverse ranking | Ranking golden |
| Search during unsupported intent | Provider access: 1 instead of 0 |
| Retry a simulated provider timeout | Provider access: 2 instead of 1 |
| Return the valid portion of an incomplete catalog | Catalog grounding |
| Return a malformed recommendation record | Response contract |

A defect counts as detected only when its required invariant appears among the
failures. An incidental exception does not count. Another test replaces the
evaluator with an always-passing result and requires the audit to report ten
undetected faults. The command exits nonzero if a scenario fails or a seeded
fault escapes detection. This tests these particular oracles; it is not an
exhaustive mutation score or an external benchmark.

## Reproduce and inspect

From the repository root with the documented Python dependencies installed:

```powershell
py -3.14 -B -m unittest discover -s tests -v
py -3.14 -B -m unittest discover -s tests -p test_v013_regressions.py -v
py -3.14 -B -m evaluation --output evaluation_report.json
$report = Get-Content evaluation_report.json -Raw | ConvertFrom-Json
$report.summary
$report.fault_injection.cases | Format-Table fault, detected, required_detection, expected_provider_calls, actual_provider_calls
$report.scenarios | Where-Object { $_.name -in @('exclusion_scope_spicy', 'mixed_valid_and_invalid_catalog', 'text_provider_timeout') } | ConvertTo-Json -Depth 12
```

The report contains expected/observed outcomes and provider calls per scenario,
plus application version, execution mode, catalog/scenario hashes, and SHA-256
hashes of relevant implementation and test files in the uncommitted working tree.
This binds a local report to reviewable source bytes, not to an invented release
commit. It excludes timestamps and random request IDs.
Repeated evaluation and report-file equality are tested. No credentials, network
commerce calls, new dependencies, or infrastructure are involved.

## Explicit limits

- This remains a bounded English grammar. The reference grammar can still have
  untested semantic errors; schema agreement and these counterexamples do not
  establish general language understanding.
- Missing completeness flags preserve legacy provider-reported ingredient matching.
  Plausible unmarked omissions cannot be detected. A true completeness flag is an
  asserted provider fact, not independent dietary/allergy certification. Future
  adapters must not fabricate it from a partial response.
- Budget applies to catalog item price. Fees, taxes, quantities, inventory,
  serviceability, nutrition, and real checkout totals are not verified.
- Timeout tests inject timeout failures. They establish classification and no
  implicit retry, not actual network deadline/cancellation behavior.
- Route evaluation does not execute HTTP serialization. It records a normally
  returned malformed object as a response-contract failure; separate API tests
  verify the actual HTTP 500 behavior.
- There are no live Swiggy, OAuth, spending, concurrency, load, or production
  reliability claims. The server remains intended for local development.
